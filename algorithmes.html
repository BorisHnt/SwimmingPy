00

Avant de coder

Méthode d'identification

En exam, le plus dur n'est pas toujours d'écrire Python. Le plus dur est de reconnaître le problème. Si le sujet parle de "plus court", pense souvent BFS. S'il parle de "toutes les dépendances avant X", pense tri topologique. S'il parle de "sous-chaîne contiguë", pense fenêtre glissante ou double boucle. S'il parle de "minimum/maximum optimal sur des préfixes", pense programmation dynamique.

Comment lire un sujet quand on débute

Lis d'abord la sortie demandée, pas le code que tu imagines. Si la sortie est un booléen, on cherche souvent une preuve ou un contre-exemple. Si la sortie est une liste ordonnée, l'ordre fait partie du problème. Si la sortie est un nombre minimum ou maximum, il faut se demander si une solution locale suffit ou s'il faut garder une mémoire des meilleurs choix.

Ensuite, cherche le verbe principal. "Compter" pointe vers un dictionnaire ou une boucle. "Trouver le plus court" pointe vers BFS. "Installer dans le bon ordre" pointe vers dépendances et tri topologique. "Toutes les possibilités" peut pointer vers backtracking. "Sous-chaîne contiguë" veut dire que tu n'as pas le droit de sauter des caractères.

Question 1 : quelle forme ?

Chaîne, liste, matrice, graphe, intervalles ou dictionnaire. La forme de la donnée donne déjà la moitié de l'algo.

Question 2 : quelle opération revient ?

Tester l'appartenance, parcourir des voisins, minimiser un nombre, garder un ordre, compter, trier ou chercher un chemin.

Question 3 : quel piège ?

Vide, taille 1, doublons, cycle, bornes de grille, ordre stable, mutation de l'entrée, ou complexité trop lente.

Réflexe à annoncer : Je choisis la structure qui rend l'opération principale simple. Si je cherche souvent une valeur, je prends un `set` ou un `dict`. Si je cherche un plus court chemin, je prends une file BFS. Si je dois revenir en arrière, je prends DFS/backtracking.

Erreur de débutant·e

Partir directement sur du code parce qu'un exemple semble simple. Les exemples visibles sont souvent gentils ; les tests cachés vérifient les cas limites. Avant de coder, écris au moins mentalement : entrée vide, un seul élément, doublons, élément absent, cycle, grande taille.

01

Chaînes

Palindromes

Un palindrome se lit pareil dans les deux sens. Les exercices autour des palindromes vérifient trois niveaux : tester une chaîne complète, trouver des sous-chaînes palindromiques, ou optimiser un découpage en morceaux palindromes.

À reconnaître

  • Le sujet parle de miroir, de chaîne inversée, de sous-chaîne symétrique.
  • On demande le plus long palindrome, tous les palindromes, ou un découpage minimal.
  • Les espaces, la casse ou la ponctuation peuvent devoir être ignorés.

Idée claire

Pour tester une chaîne entière, `s == s[::-1]` suffit souvent. Pour éviter de copier la chaîne, utilise deux pointeurs : un à gauche, un à droite, puis tu avances vers le centre.

Pour trouver les palindromes internes, pars d'un centre et agrandis tant que les deux côtés sont égaux. Il faut tester les centres impairs (`aba`) et pairs (`abba`).

Déroulé pas à pas

  1. Normalise si le sujet le demande : casse, espaces, ponctuation. Ne mélange pas cette étape avec l'algo.
  2. Pour un test simple, compare le premier et le dernier caractère, puis rapproche les deux pointeurs.
  3. Pour chercher des palindromes internes, choisis un centre et agrandis vers la gauche et la droite.
  4. Teste deux centres à chaque position : un centre sur une lettre, et un centre entre deux lettres.
  5. Quand l'égalité casse ou qu'une borne sort de la chaîne, le palindrome maximal autour de ce centre est terminé.

Pourquoi les centres suffisent

Tout palindrome a forcément un milieu. Pour `racecar`, le milieu est `e`. Pour `abba`, le milieu est l'espace entre les deux `b`. Si tu testes tous les milieux possibles et que tu agrandis tant que les côtés correspondent, tu ne peux pas rater un palindrome. 

def expand(s, left, right):
    while left >= 0 and right < len(s) and s[left] == s[right]:
        left -= 1
        right += 1
    return s[left + 1:right]
Simple O(n) Tous les centres O(n²) Piège oublier les palindromes pairs

Recherche texte

Sous-chaînes et KMP

Une sous-chaîne est un morceau contigu `s[i:j]`. Si tu testes toutes les sous-chaînes avec deux boucles, tu as déjà O(n²) morceaux. Si chaque test relit le morceau, tu peux monter à O(n³). Il faut donc savoir quand une double boucle suffit et quand il faut un algo plus fin.

KMP sert à rechercher un motif dans un texte sans revenir en arrière dans le texte. Il construit une table LPS : pour chaque position du motif, elle indique la longueur du plus long préfixe qui est aussi suffixe. Quand une comparaison échoue, on sait où reprendre dans le motif au lieu de repartir de zéro.

Comprendre LPS sans panique

Imagine que tu cherches `abab` dans un texte. Si tu as déjà reconnu `aba` puis que le caractère suivant échoue, tu n'as pas besoin d'oublier tout ce que tu sais. Le début `a` peut aussi être la fin de ce qui vient de matcher. La table LPS encode exactement ce recyclage.

LPS veut dire : "si j'échoue ici, quelle longueur de début du pattern est encore utilisable ?" Ce n'est pas une table sur le texte, c'est une table sur le motif. C'est pour cela qu'on la construit une seule fois avant la recherche.

Plan de KMP

  1. Construis la table LPS du pattern.
  2. Avance dans le texte avec `i` et dans le pattern avec `j`.
  3. Si les caractères matchent, avance les deux.
  4. Si `j` atteint la fin du pattern, tu as trouvé une occurrence.
  5. Si ça casse, remplace `j` par `lps[j - 1]` au lieu de reculer `i`.
# Double boucle pour énumérer les sous-chaînes
for start in range(len(s)):
    for end in range(start + 1, len(s) + 1):
        sub = s[start:end]
Image mentale : KMP garde la mémoire de ce qui a déjà matché dans le pattern. Si le début du pattern ressemble à sa fin, on réutilise cette information.
Naïf O(n × m) KMP O(n + m) Piège occurrences qui se chevauchent
03

Listes et chaînes

Fenêtre glissante, deque et Kadane

La fenêtre glissante sert quand le sujet parle d'un morceau contigu qui avance : sous-liste, sous-chaîne, fenêtre de taille `k`, plus longue zone sans doublon, somme maximale contiguë. L'idée est de ne pas recalculer toute la fenêtre à chaque déplacement.

Image mentale

Une fenêtre, c'est deux index : `left` et `right`. Tout ce qui est entre les deux est la zone actuellement étudiée. Quand tu avances `right`, tu ajoutes un élément à droite. Quand la fenêtre devient invalide, tu avances `left` pour retirer des éléments à gauche.

La puissance de cette méthode vient du fait que chaque élément entre dans la fenêtre une fois et en sort une fois. Même avec une boucle `while` à l'intérieur, la complexité reste souvent O(n), parce que `left` ne revient jamais en arrière.

Fenêtre fixe

La taille est connue, par exemple `k`. La fenêtre commence à `i` et finit à `i + k`. Il y a `len(arr) - k + 1` fenêtres.

Fenêtre variable

La taille bouge selon une condition. On avance `right`, puis on avance `left` tant que la fenêtre devient invalide.

Deque monotone

Pour le maximum de chaque fenêtre, la deque garde des indices candidats au maximum. Les valeurs inutiles sont retirées.

# Fenêtre variable : plus longue zone sans doublon
left = 0
seen = set()
for right, value in enumerate(values):
    while value in seen:
        seen.remove(values[left])
        left += 1
    seen.add(value)

Kadane est une fenêtre glissante spécialisée pour la somme maximale d'une sous-liste contiguë. À chaque nombre, tu décides si tu continues la somme courante ou si tu repars de ce nombre. C'est le bon outil quand des nombres négatifs peuvent casser une somme.

À ne pas confondre

Une sous-liste contiguë n'est pas une sélection libre d'éléments. Pour `[4, -1, 2]`, tu peux prendre les trois ensemble, mais tu ne peux pas prendre `4` et `2` en sautant `-1` si le sujet dit "contigu".

Fenêtre simple O(n) Deque max O(n) Kadane O(n)

Listes

Rotations

Une rotation coupe une liste en deux morceaux puis inverse leur ordre. Pour une rotation à droite de `k`, les `k` derniers éléments passent devant. Pour une rotation à gauche de `k`, les `k` premiers passent derrière. 

k %= len(values)
right = values[-k:] + values[:-k]
left = values[k:] + values[:k]

Le `% len(values)` est essentiel : tourner de 12 positions une liste de 5 éléments revient à tourner de 2 positions. Sans modulo, tu peux faire trop de travail ou te tromper sur les slices.

Exemple mental

  1. Liste : `[1, 2, 3, 4, 5]`, rotation droite de 2.
  2. Les 2 derniers éléments sont `[4, 5]`.
  3. Le reste est `[1, 2, 3]`.
  4. On met la fin devant : `[4, 5] + [1, 2, 3]`.
  5. Résultat : `[4, 5, 1, 2, 3]`.

Cas limite

Si la liste est vide, `k % len(values)` provoque une division par zéro. Il faut gérer `if not values: return values` avant le modulo.

Slicing O(n) In-place par reverse O(n), O(1) Piège gauche vs droite
05

Dictionnaires

Comptage, fréquences et anagrammes

Dès qu'un sujet demande "combien de fois", "même composition", "fréquence", "doublon", ou "anagramme", pense dictionnaire ou `Counter`. Le dictionnaire associe une clé à un nombre. La clé peut être un caractère, un mot, un nombre ou une signature calculée. 

freq = {}
for char in text.lower():
    freq[char] = freq.get(char, 0) + 1

Pour les anagrammes, deux chaînes sont équivalentes si elles ont les mêmes fréquences de caractères. Trier les chaînes fonctionne aussi, mais coûte O(n log n), alors qu'un comptage est O(n).

Pourquoi le dictionnaire est le bon outil

Une liste répond bien à "quels éléments sont dans l'ordre ?". Un dictionnaire répond bien à "combien de fois ai-je vu cette clé ?". Dans un exercice de fréquence, l'ordre du texte n'est souvent pas la donnée importante ; ce qui compte, c'est le nombre d'occurrences par caractère ou par mot.

Pour un mot comme `banana`, le dictionnaire devient `{b: 1, a: 3, n: 2}`. Deux mots sont anagrammes si leurs dictionnaires de fréquence sont identiques après normalisation.

Dict insertion moyenne O(1) Counter lisible et sûr Piège normaliser casse et espaces

Ordre

Tri personnalisé

`sorted` crée une nouvelle liste triée. `list.sort()` modifie la liste en place et renvoie `None`. Pour les exercices, `sorted` est souvent plus simple parce que la fonction peut directement retourner le résultat.

La clé de tri transforme chaque élément en valeur comparable. Pour trier par plusieurs critères, retourne un tuple : Python compare d'abord le premier élément du tuple, puis le second en cas d'égalité, puis le troisième. 

words = sorted(words, key=lambda word: (len(word), word.lower(), word))
Tri stable : Si deux éléments ont la même clé, Python garde leur ordre relatif. On peut donc faire plusieurs tris successifs du critère secondaire vers le critère principal.

Comment penser une clé de tri

Ne pense pas "je trie avec plein de conditions". Pense plutôt "pour chaque élément, je fabrique une carte d'identité comparable". Pour un mot, cette carte peut être `(longueur, version minuscule, mot original)`. Python trie ensuite ces cartes de gauche à droite.

Si deux mots ont la même longueur, Python regarde le deuxième critère. Si le deuxième critère est aussi égal, il regarde le troisième. C'est beaucoup plus simple que d'écrire une fonction avec des `if` imbriqués.

Graphes orientés

Tri topologique

Le tri topologique sert quand certaines choses doivent arriver avant d'autres : cours à valider, paquets à installer, tâches de build, dépendances. Le graphe doit être orienté et sans cycle. S'il y a un cycle, aucun ordre valide n'existe.

Le modèle mental

Imagine des tâches avec des cadenas. Une tâche avec zéro dépendance n'a aucun cadenas : tu peux la faire tout de suite. Quand tu fais cette tâche, elle peut enlever un cadenas sur d'autres tâches. Le tri topologique répète cette idée jusqu'à ce que tout soit fait.

Si à un moment il reste des tâches, mais aucune n'a zéro dépendance, elles se bloquent entre elles. C'est un cycle. Dans ce cas, le bon résultat est souvent une liste vide, parce qu'aucun ordre ne peut respecter toutes les contraintes.

Kahn

On calcule le nombre de dépendances restantes de chaque nœud. Les nœuds à zéro dépendance entrent dans une file. Quand on en sort un, on réduit le degré des nœuds qui dépendaient de lui.

DFS

On visite les dépendances en profondeur. Un coloriage à trois états aide : blanc non vu, gris en cours, noir terminé. Revoir un gris signifie cycle.

# Kahn : si tout n'est pas sorti, il reste un cycle
if len(order) != number_of_nodes:
    return []

Plan de Kahn

  1. Liste tous les nœuds, même ceux qui n'ont pas de dépendances.
  2. Calcule `in_degree[node]`, le nombre de dépendances restantes.
  3. Mets dans une file tous les nœuds avec `in_degree == 0`.
  4. Sors un nœud, ajoute-le au résultat, puis décrémente les nœuds qui dépendaient de lui.
  5. Si un voisin tombe à zéro, ajoute-le dans la file.
  6. À la fin, compare la taille du résultat au nombre total de nœuds.
Complexité O(V + E) Structure queue + in-degree Piège nœuds déconnectés
08

Optimisation

Programmation dynamique

La programmation dynamique sert quand le résultat optimal d'un problème dépend de résultats optimaux plus petits. Le signe le plus clair : tu peux définir une phrase du type `dp[i] = meilleure réponse pour les i premiers éléments`.

Pourquoi la DP existe

Certains problèmes te font recalculer les mêmes choses encore et encore. Par exemple, si tu essaies tous les découpages d'une chaîne en palindromes avec une récursion naïve, le même préfixe peut être analysé plusieurs fois. La DP dit : dès que j'ai calculé une réponse pour un morceau, je la garde.

Il y a deux formes courantes. La mémoïsation part d'une fonction récursive et ajoute un cache. La tabulation construit un tableau du plus petit problème vers le plus grand. Les deux reposent sur la même idée : ne pas refaire deux fois le même sous-problème.

Pour le découpage minimal en palindromes, `dp[i]` peut représenter le nombre minimal de morceaux palindromes pour `s[:i]`. On teste chaque dernier morceau possible `s[j:i]`. S'il est palindrome, alors on peut prolonger la solution de `s[:j]`.

Questions à se poser pour une DP

  1. Quelle est la petite version du problème ? Préfixe, suffixe, case, quantité, intervalle ?
  2. Que signifie exactement une case `dp` ? Écris une phrase complète.
  3. Quelle est la valeur de départ ? Souvent `dp[0] = 0` ou une première case connue.
  4. Comment passer d'un état plus petit à un état plus grand ?
  5. Est-ce qu'on cherche un minimum, un maximum, un booléen, ou un nombre de possibilités ?
dp = [float("inf")] * (len(s) + 1)
dp[0] = 0
for i in range(1, len(s) + 1):
    for j in range(i):
        if is_palindrome(s[j:i]):
            dp[i] = min(dp[i], dp[j] + 1)
Point critique : Dis exactement ce que contient `dp`. Si tu comptes les morceaux, le nombre de coupes vaut morceaux moins un.
09

Recherche rapide

Hash set et hash map

Un `set` répond vite à la question "ai-je déjà vu cette valeur ?". Un `dict` répond vite à la question "quelle information est associée à cette valeur ?". C'est le cœur de `contains duplicate`, `two sum`, intersection, fréquences et caches simples. 

seen = {}
for index, value in enumerate(nums):
    need = target - value
    if need in seen:
        return [seen[need], index]
    seen[value] = index

Dans Two Sum, on ne cherche pas directement deux nombres. Pour chaque nombre, on cherche son complément. Cette inversion de perspective transforme une double boucle O(n²) en boucle simple O(n).

Pourquoi ça accélère autant

Dans la version naïve, pour chaque nombre, tu reparcours tous les autres nombres. Tu poses donc beaucoup de fois la même question : "est-ce que cette valeur existe ?" Un dictionnaire transforme cette question en recherche directe.

Pour `target = 9` et `value = 2`, tu ne cherches pas tous les couples. Tu calcules `need = 7`, puis tu demandes au dictionnaire si `7` a déjà été vu. Si oui, tu as le couple immédiatement. Sinon, tu mémorises `2` pour les prochains tours.

Piège des doublons

Pour `target = 6` et une liste qui contient un seul `3`, tu n'as pas le droit d'utiliser le même index deux fois. C'est pour cela qu'on cherche d'abord le complément dans les valeurs déjà vues, puis seulement ensuite on ajoute la valeur courante.

Set appartenance O(1) moyenne Dict valeur associée O(1) moyenne Piège doublons et indices

Temps et segments

Intervalles

Les intervalles apparaissent avec des réunions, périodes, plages horaires, segments ou réservations. Le premier réflexe est presque toujours de trier par début. Une fois triés, les conflits deviennent locaux : tu compares l'intervalle courant avec le dernier intervalle gardé.

Pourquoi trier change tout

Sans tri, un intervalle peut chevaucher un autre placé n'importe où dans la liste. Après tri par début, si l'intervalle courant ne chevauche pas le dernier intervalle fusionné, il ne chevauchera pas non plus les intervalles encore plus anciens. Le problème devient linéaire après le tri.

Pour fusionner, on garde une liste `merged`. Le dernier élément de `merged` représente la plage active la plus à droite. Si le début du nouvel intervalle est avant ou égal à la fin de cette plage, on étend la fin. Sinon, on crée une nouvelle plage. 

intervals.sort(key=lambda interval: interval[0])
merged = [intervals[0]]
for start, end in intervals[1:]:
    last = merged[-1]
    if start <= last[1]:
        last[1] = max(last[1], end)
    else:
        merged.append([start, end])

Pour les salles de réunion, on veut savoir combien d'intervalles se chevauchent au maximum. Une solution classique trie les débuts et les fins avec deux pointeurs. Une autre utilise un min-heap des fins de réunions pour réutiliser la salle qui se libère le plus tôt.

Lecture d'un chevauchement

  1. Si `start < previous_end`, les réunions se chevauchent.
  2. Si `start == previous_end`, elles se touchent mais ne se chevauchent pas.
  3. Si `start > previous_end`, il y a un trou entre les deux.
Merge O(n log n) Rooms heap ou two pointers Piège `end == start` ne chevauche pas
11

Matrices

Grilles : DFS, BFS et backtracking

Une grille est un graphe caché. Chaque case est un nœud, et ses voisines sont souvent haut, bas, gauche, droite. Dès que le sujet parle d'îlots, de chemin, de contamination, de mot à retrouver ou de zones connectées, pense parcours de graphe.

Transformer une grille en graphe

Une case `(row, col)` est un nœud. Ses voisins sont calculés avec des petits déplacements : `(+1, 0)`, `(-1, 0)`, `(0, +1)`, `(0, -1)`. Avant de lire une case voisine, tu dois vérifier qu'elle reste dans la grille. C'est l'ordre le plus important : bornes d'abord, accès ensuite.

Pour les îlots, DFS est naturel : dès que tu trouves une terre, tu comptes un nouvel îlot, puis tu marques toute la terre connectée comme visitée. Pour le plus court chemin, BFS est naturel : la première fois que tu atteins une case, tu y arrives par le chemin le plus court.

DFS

Explore à fond une zone avant de revenir. Parfait pour compter des îlots ou marquer toute une composante.

BFS

Explore par distance croissante. Parfait pour plus court chemin ou propagation minute par minute.

Backtracking

Essaie un chemin, marque la case, avance, puis annule si le chemin ne marche pas. Indispensable pour Word Search.

directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]
for dr, dc in directions:
    nr, nc = row + dr, col + dc
    if 0 <= nr < rows and 0 <= nc < cols:
        pass

Mutation ou visited ?

Tu peux marquer une case visitée en modifiant la grille, par exemple en transformant `1` en `0`. C'est simple et économise un set. Mais si le sujet interdit de modifier l'entrée, utilise un `visited`.

DFS/BFS grille O(R × C) Structure BFS deque Piège bornes avant accès

Parsing

Compression RLE

Le Run-Length Encoding remplace une suite de caractères identiques par le caractère puis son nombre d'occurrences : `aaabbc` devient `a3b2c1`. C'est un exercice de parcours linéaire et de parsing propre.

Pour compresser, garde le caractère courant et un compteur. Quand le caractère change, tu écris le couple précédent. Pour décompresser, lis un caractère puis tous les chiffres qui le suivent, car le nombre peut avoir plusieurs chiffres.

Compression pas à pas

  1. Si le texte est vide, retourne une chaîne vide.
  2. Prends le premier caractère comme caractère courant et initialise le compteur à 1.
  3. Pour chaque caractère suivant, s'il est identique, incrémente le compteur.
  4. S'il change, écris l'ancien caractère et son compteur, puis recommence avec le nouveau caractère.
  5. Après la boucle, n'oublie pas d'écrire le dernier groupe.

Décompression

Ne lis pas un seul chiffre après la lettre. Dans `a12`, le nombre est `12`, pas `1`. Il faut avancer tant que les caractères suivants sont des chiffres.

Compression O(n) Décompression O(n + sortie) Piège nombres à plusieurs chiffres

Graphes

Détection de cycle

Dans un graphe orienté, un cycle signifie qu'on peut revenir à un nœud déjà en cours de visite. C'est exactement le problème des dépendances impossibles : A dépend de B, B dépend de C, C dépend de A.

Le DFS avec coloriage est très lisible : blanc pour non visité, gris pour en cours, noir pour terminé. Si tu tombes sur un gris, tu as trouvé un cycle. Kahn détecte aussi les cycles : si après avoir retiré tous les nœuds sans dépendances il reste des nœuds, ils sont bloqués dans un cycle.

Pourquoi le gris signifie cycle

Gris veut dire : "je suis actuellement dans la pile d'appels DFS". Si pendant l'exploration tu retombes sur un nœud gris, cela signifie qu'un chemin revient vers un ancêtre qui n'a pas encore fini. C'est exactement la définition d'un cycle orienté.

Noir veut dire : "tout ce qui part de ce nœud a déjà été vérifié". Revoir un nœud noir n'est pas dangereux, parce qu'on sait déjà qu'il ne mène pas à un cycle non traité. 

WHITE, GRAY, BLACK = 0, 1, 2
if color[node] == GRAY:
    return True
DFS color O(V + E) Kahn O(V + E) Piège auto-boucle

Simulation

Matrice spirale

Les spirales sont des exercices de simulation. Tu gardes quatre limites : haut, bas, gauche, droite. Tu parcours la ligne du haut, puis la colonne de droite, puis la ligne du bas, puis la colonne de gauche, et tu resserres les limites.

Tour de spirale

  1. Va de gauche à droite sur la ligne `top`, puis augmente `top`.
  2. Va de haut en bas sur la colonne `right`, puis diminue `right`.
  3. Si `top <= bottom`, va de droite à gauche sur la ligne `bottom`, puis diminue `bottom`.
  4. Si `left <= right`, va de bas en haut sur la colonne `left`, puis augmente `left`.
  5. Répète tant que les limites ne se croisent pas.

L'autre méthode consiste à garder une direction courante et à tourner quand la prochaine case sort de la grille ou est déjà remplie. Les deux approches marchent ; les limites explicites sont souvent plus faciles à expliquer en correction.

Lecture O(R × C) Génération n² O(n²) Piège ligne/colonne restantes

Graphe implicite

Word Ladder

Word Ladder est un BFS sur un graphe qu'on ne construit pas toujours explicitement. Chaque mot est un nœud. Deux mots sont voisins s'ils diffèrent d'une seule lettre. Comme on cherche la transformation la plus courte, BFS est le bon choix.

Pourquoi c'est un graphe implicite

Le sujet ne te donne pas une liste d'arêtes comme `hit -> hot`. Pourtant, ces arêtes existent si deux mots ne diffèrent que d'une lettre. On dit que le graphe est implicite parce que tu peux générer les voisins à la demande au lieu de tous les stocker dès le départ.

BFS est obligatoire si on veut le plus court nombre de transformations. DFS peut trouver un chemin, mais pas forcément le plus court. Avec BFS, tous les mots à distance 2 sont traités avant les mots à distance 3.

À chaque mot, tu génères toutes les variations possibles en changeant une position par les 26 lettres. Si le mot généré existe dans le dictionnaire et n'a pas été visité, tu l'ajoutes à la file avec une distance augmentée de 1.

Générer les voisins

  1. Pour chaque position du mot, remplace la lettre par `a`, puis `b`, puis `c`, etc.
  2. Ignore le mot généré s'il n'est pas dans `word_list`.
  3. Ignore-le aussi s'il a déjà été visité.
  4. Sinon, ajoute-le à la file avec une distance augmentée.
queue = deque([(begin, 1)])
words = set(word_list)
while queue:
    word, distance = queue.popleft()
Piège majeur : Si le mot de fin n'est pas dans la liste, il faut souvent retourner 0 immédiatement. Sinon tu fais un BFS inutile.

Heap

Meeting scheduler

Meeting Scheduler mélange tri d'intervalles et heap. On trie les réunions par heure de début. Le heap contient les salles occupées, triées par leur heure de libération. La salle qui se libère le plus tôt est toujours au sommet.

Pourquoi un heap

À chaque nouvelle réunion, tu dois répondre à une question : "quelle salle se libère le plus tôt ?" Si tu parcours toutes les salles à chaque fois, tu perds du temps. Un min-heap garde automatiquement la plus petite heure de fin au sommet.

Le heap ne trie pas toute la liste comme un tableau trié visible. Il garantit seulement que le plus petit élément est accessible rapidement. C'est exactement ce qu'il nous faut ici : on ne veut pas toutes les salles triées, seulement la prochaine salle disponible.

Pour chaque réunion, si la salle au sommet se libère avant ou exactement au début de la réunion, on peut la réutiliser. Sinon, il faut créer une nouvelle salle. Le nombre maximal de salles créées donne le minimum nécessaire.

Déroulé

  1. Trie les réunions par heure de début.
  2. Regarde la salle qui se libère le plus tôt dans le heap.
  3. Si `end_time <= start`, réutilise cette salle.
  4. Sinon, crée une nouvelle salle.
  5. Ajoute la réunion courante dans le heap avec sa nouvelle heure de fin.
heap = []  # (end_time, room_id)
for start, end, name in meetings:
    if heap and heap[0][0] <= start:
        free_end, room = heappop(heap)
    else:
        room = new_room()
    heappush(heap, (end, room))
